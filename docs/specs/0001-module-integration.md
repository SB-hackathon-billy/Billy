이 문서는 연동 전에 결정할 항목을 정리한 출발점이다. API·새 예약 정책은 아직 확정하지 않았다. 2·3번 기능을 이번 문서 정리에서 구현하지 않는다.

## 목표와 경계

접수 결과가 게시 물품 탐색과 대여 신청으로 연결되도록 한다. 1번은 기존 동작을 유지하고, 2번은 사진 기반 등록·게시 원장, 3번은 조회·가용성·대여 상태를 담당한다. 기존 MVP의 후보·협상·가격·결제 미리보기 구조는 2·3번 설계의 영구 제약이 아니다.

1번의 채팅·보이스콜·신청서 확인·안내 기능을 재작성하거나 그림에 있는 미구현 1번 기능을 추가하는 것은 범위 밖이다. 로그인·실제 결제·실제 기관 API 연동도 분담도의 범위 밖이며 이번 준비 문서로 추가하지 않는다.

## 데이터 소유권 목표

| 데이터                          | 소유 모듈 | 연동 원칙                                    |
| ------------------------------- | --------- | -------------------------------------------- |
| 대화·신청 초안·도구 실행 이력   | 1         | 타 모듈에서 직접 수정하지 않음               |
| 이미지·등록 초안·게시 물품      | 2         | 사람 확인 후 게시, 3번에 게시 물품 조회 제공 |
| 예약·점유·대기·소유자 응답·알림 | 3         | 사람의 명령을 서버에서 검증, 중복 예약 방지  |

이미지/초안/물품 ID와 예약 ID는 같은 종류로 취급하지 않는다. 소유자·신청자는 서버 컨텍스트에서 결정한다. 물품 수정이 기존 예약을 소급 무효화하지 않도록 스냅샷·참조 정책을 정해야 한다.

## API 초안과 현재 호출의 차이

| 영역        | 현재 호출                                                  | 분담도 제안                                            | 호환 방침                                       |
| ----------- | ---------------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------- |
| 접수 텍스트 | `POST /agent-turns`, `GET /agent-tasks/{id}`               | `POST /requests/{id}/messages`                         | 제안 경로를 이유로 1번 호출을 바꾸지 않음       |
| 접수 음성   | `/voice-sessions` 계열, body의 requestId                   | `/requests/{id}/voice-sessions`                        | 기존 세션·종료·안내 오디오 경로 보존            |
| 신청서      | `PATCH /requests/{id}/draft`, `POST /requests/{id}/search` | `PATCH /requests/{id}` 등                              | 입력·버전·응답 의미 보존. 필요 시 3번 쪽 어댑터 |
| 등록        | 현재 seed 중심 `/items` 조회                               | `/images`, `/item-drafts`, `/items` CRUD               | 2번 새 계약 필요                                |
| 탐색        | `/items`, `/requests/{id}/candidates`                      | `/catalog`, `/catalog/{itemId}/availability`           | 3번 새 계약과 접수 결과 변환 필요               |
| 대여·대기   | `/negotiations`, 선택·미리보기                             | `/reservations`, `/waitlist-entries`, `/notifications` | 3번 상태·마이그레이션·기존 호출자 전환 필요     |

위 경로는 `/api/v1` 아래의 상대 경로다. 그림의 `expectedVersion`과 현재 `expectedRequestVersion` 등은 같다고 가정하지 않는다. 새 계약은 필드 타입·nullable·오류·응답 envelope·멱등 키·버전·인증 주체와 정상/실패 JSON 예제를 포함해야 한다. 이 표만으로 API 구현을 시작하지 않는다.

## 1번 보존과 전환 순서

1. 각 모듈은 담당 데이터·기능에 대한 세부 명세와 합성 API 샘플을 먼저 작성한다.
2. 2번의 게시 물품 조회와 3번의 탐색·대여 API를 독립적으로 검증한다. 등록 초안은 게시 물품처럼 노출하지 않는다.
3. 2·3번 쪽 호환 계층에서 기존 접수 DTO와 새 DTO를 변환한다. 1번 전용 파일·프롬프트·수집 완료·종료 조건은 바꾸지 않는다.
4. 접수 → 검색 → 사용자 확인 → 신청 → 소유자 응답 흐름을 연결하고 버전 충돌·재시도·중복 점유·AI 실패를 확인한다.
5. 전환 전 기존 데이터 보존·ID 매핑·롤백 경로를 구체화한다. 검증된 전환 전에는 기존 검색/예약 경로를 제거하지 않는다.

공용 코드의 실제 변경 목록, 데이터 migration, 트래픽 전환과 롤백 명령은 세부 명세에서 채운다. 호환 계층 없이 1번 변경이 필요한 항목은 별도 변경 제안으로 남긴다.

## 연동 전 결정할 사항

| 질문                                          | 영향              | 결정 전 진행 가능한 작업                            |
| --------------------------------------------- | ----------------- | --------------------------------------------------- |
| 이미지 저장·업로드 크기/형식·삭제 정책        | 2                 | 등록 화면·초안 편집·실패 시 직접 작성               |
| 게시 물품 DTO와 조회·비활성화 계약            | 2→3               | 각 모듈의 내부 구조와 합성 샘플 작성                |
| 초안/예약 ID·상태·이력의 분리                 | 1↔3               | 3번 예약 모델 제안과 기존 접수 소비자 조사          |
| 기존 협상·추천 가격·결제 미리보기의 유지/폐기 | 3, 접수 결과 안내 | 새 대여 정책 명세·상태 전이·중복 예약 검사          |
| 1번 기대 DTO와 새 catalog/예약 DTO 변환       | 1↔3               | 3번 어댑터 설계. 1번은 변경하지 않음                |
| 이벤트·알림·대기 순서·만료·취소               | 3                 | 알림/대기 명세와 조회 UI                            |
| 배포 단위·인증 전달·API prefix/버전           | 공용              | 모듈 내부 개발·mock 계약. 임의의 운영 URL 확정 금지 |

모든 항목은 현재 미결정이다. 관련 명세·결정 근거를 연결한 뒤 해당 범위를 `ready`로 전환한다.

## 검증 기준 초안

- 1번 전용 파일 검사 통과 + 공용 변경의 접수 회귀 검증.
- 사진 분석 실패 시 직접 수정 가능, 확인 전 게시 없음.
- 3번 탐색 결과가 2번 게시 정보와 가용성을 반영함.
- 사용자의 명시적 신청, 소유자 응답, 동시 승인에서 중복 점유 없음.
- 취소·만료 후 점유 해제, 대기 알림 뒤 재신청 시 가용성 재검사, 자동 예약 없음.
- 기존 접수의 수정·불완전 초안·종료 재시도·최신 결과 안내가 유지됨.

후속 기능 검증은 **미실행**이다. 이 문서 작성과 보호 설정만으로 통합 완료를 선언하지 않는다.
