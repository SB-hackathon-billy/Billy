## 1. 문제와 목표

누가 어떤 행동을 할 때 무엇이 달라지는지 적는다. 이번 변경의 포함·제외 범위를 적는다. 과거 MVP의 제한을 자동으로 가져오지 않는다.

## 2. 기존 기능과 겹침

| 기존 기능·파일·API | 새 기능   | 유지/대체/통합/폐기 | 최종 단일 구현 위치 | 기존 호출자 처리    |
| ------------------ | --------- | ------------------- | ------------------- | ------------------- |
| 실제 코드 경로     | 변경 내용 | 결정                | 모듈·경로           | 호환/전환/제거 시점 |

중복이 없으면 검색한 경로와 근거를 적는다. 임시 이중 구현은 종료 조건을 반드시 적는다.

## 3. 1번 보존과 공용 코드 영향

- 1번의 입력·출력·프롬프트·화면·라우트·동작이 유지되는 근거:
- 공용 파일별 변경 부분과 접수 소비자:
- 필요한 호환 어댑터의 위치·입출력 변환:
- 1번 기능 수정이 필요한 미결정 사항(구현하지 않음):
- 관련 회귀 테스트와 수동 확인:

## 4. 모듈·데이터 소유권

| 데이터 | 소유 모듈 | 읽는 모듈·API | 쓰는 모듈·명령   | ID·수명·삭제/비활성화 |
| ------ | --------- | ------------- | ---------------- | --------------------- |
| 리소스 | 2 또는 3  | 조회 계약     | 소유 모듈만 변경 | 정책                  |

타 모듈 DB 직접 쓰기와 중복 원장을 만들지 않는다. 1번 초안과 3번 예약은 같은 엔터티로 가정하지 않는다.

## 5. API·이벤트 계약

| 제공 모듈 | 소비 모듈        | 메서드·경로/이벤트 | 입력·출력 스키마    | 권한·오류      |
| --------- | ---------------- | ------------------ | ------------------- | -------------- |
| 2 / 3     | 1 / 2 / 3 / 화면 | 정확한 경로        | 필드·타입·필수/null | 식별·권한·코드 |

각 경로에 정상 요청/응답과 실패 JSON 예시를 첨부한다. 인증 주체, 페이지네이션, UTC 시각, KRW 정수, 버전 충돌, 멱등 키, 재시도·타임아웃, 삭제·비활성화 후 조회를 명시한다. 기존 1번과 다른 envelope/필드는 어댑터 변환을 명시한다. 샘플에는 합성 데이터만 사용한다.

## 6. 상태·동시성·실패

상태 전이, 사람의 확인 시점, 중복 실행/예약 방지, 권한 없는 호출, AI 실패·늦은 결과, 비활성 물품, 취소·만료·대기를 구체화한다. 적용하지 않는 항목은 이유를 적는다.

1. 기존 데이터와 API 사용처 조사:
