# 후속 변경 명세

명세는 AI가 `write-spec` 스킬로 작성하고 사람은 결정 질문에 답한다. 규모 판정과 절차는 [AI 작업 흐름](../current/AI_WORKFLOW.md)을 따른다.

| 종류   | 템플릿                            | 사용                                                                         |
| ------ | --------------------------------- | ---------------------------------------------------------------------------- |
| `card` | [CARD_TEMPLATE](CARD_TEMPLATE.md) | 2·3번 내부 새 기능·동작 변경·대체                                            |
| `full` | [TEMPLATE](TEMPLATE.md)           | 모듈 간 API·이벤트, 데이터 소유권, DB 스키마, 공용 파일의 1번 사용 부분 변경 |

번호는 다음 빈 번호를 사용한다. 구현 중에는 같은 명세를 갱신하고, 이미 적용된 결정을 바꾸면 새 명세에서 대체 관계를 연결한다.

| ID   | 명세                                                                    | 종류   | 상태          | 적용 범위                                                                                       |
| ---- | ----------------------------------------------------------------------- | ------ | ------------- | ----------------------------------------------------------------------------------------------- |
| 0001 | [3모듈 연동 준비](0001-module-integration.md)                           | `full` | `draft`       | 현재 MVP와 2·3번 개발의 겹침, 1번 호환 경계, 연동 전 결정할 항목                                |
| 0002 | [2번 AI 물품 등록](0002-item-registration.md)                           | `full` | `implemented` | 사진 기반 등록 초안·게시·비활성화, `items` 호환 투영                                            |
| 0003 | [음성 접수 통화 화면·승인 후 예약 신청](0003-voice-call-reservation.md) | `full` | `implemented` | 캐릭터·체크리스트·승인 바텀시트, `request_reservation` 도구·백그라운드 재시도, 센터 서비스 시연 |

현재 확정된 2·3번 연동 API 명세는 없다. 0001의 미결정 사항을 채우거나 범위별 명세로 분리한 뒤 구현한다. 2·3번 내부의 독립 작업은 해당 범위 명세를 먼저 작성하고 진행할 수 있다. 개인별 담당 배정은 이 목록에 적지 않는다.
