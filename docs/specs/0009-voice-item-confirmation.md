## 1. 문제와 목표

인식한 물품을 사용자가 확인·선택하고, AI가 작성하는 동안 상태를 표시한다. 받는 장소 아래 예산이 잘리고 점선만 남는 문제를 수정한다.

## 2. 기존 기능과 겹침

현재 `/rental`의 `VoiceCallPage.tsx`, `call-client.ts`, `voice-call.css`에 통합한다. `/rental/classic`, 공용 CSS·라우팅은 변경하지 않는다.

## 3. 1번 보존과 공용 코드 영향

기본 접수 동결 규칙에 대한 이번 사용자의 명시적 수정 요청을 근거로 위 UX만 변경한다. 해시 보호 파일·기준·검사기는 그대로 둔다. 발화 revision 검사, 서버 추출, 사람의 최종 승인, 예약 도구와 재시도를 유지한다. 읽기 전용 reviewer 검토와 회귀 검사를 수행한다.

## 4. 모듈·데이터 소유권

물품 확인은 화면의 임시 상태다. 실제 재고 선택·예약 상태를 변경하지 않는다. 서버 소유권 변경이나 중복 원장은 없다.

## 5. API·이벤트 계약

기존 `/voice-sessions`, `/tasks`, `/intake-approvals` 계약을 유지한다. 새 HTTP·DB·이벤트 스키마가 없어 새 JSON 예시는 없다. 클라이언트 내부 processing 콜백으로 작성 상태를 전달한다.

## 6. 상태·동시성·실패

- 추출한 물품에 ‘이 물품이 맞나요?’와 예/아니요 선택을 제공한다. 아니요는 다시 말하도록 안내한다.
- 물품명·분류가 바뀌면 확인을 초기화한다. 날짜·장소 수정은 동일 물품의 확인을 유지한다.
- 물품 확인 전·새 발화 처리 중·이전 task의 결과만 있는 동안 최종 승인으로 넘어가지 않는다.
- 서버 READY는 추출 완료가 아니다. 이전 form task ID가 유지되는 동안 작성 중을 유지한다.
- 통화 중단·시작 시 작성 상태를 정리한다. 체크리스트 영역만 스크롤하며 통화 제어는 유지한다. 연결 점선을 제거한다.
- 추가 사용자 요청으로 ‘성북구 1인가구 이용 자격’ 행을 화면과 진행률에서 제외한다. 최종 신청의 자격 검증은 유지한다.
- 최종 승인은 서버 completion의 task ID와 inputRevision까지 일치해야 한다. 폴링 사이 놓친 이전 결과가 새 발화 결과로 보이더라도 최종 신청은 차단한다.

## 7. 전환·롤백

웹 변경만 적용한다. 마이그레이션이 없으며 롤백은 해당 웹 변경을 되돌린다.

## 9. 미결정

없음. 실제 재고 후보 선택은 기존 최종 승인 이후 검색 흐름을 유지한다.

## 10. 완료·대체 기록

후속 사용자 요청(2026-11-06)에 따라 화면의 ‘AI가 신청서를 작성 중이에요’ 문구와 작성 상태 안내 행은 제거한다. 처리 중 상태는 최신 추출·승인 가드와 캐릭터 상태에만 사용한다. 체크리스트 이용 자격 행 제거는 유지한다.

구현 경로는 voice-call 전용 파일에 한정한다. reviewer 검토에서 최종 승인 최신성 차단과 보호 파일 22개 보존을 확인했다. 실제 사람의 발화·마이크·모델 응답은 별도 수동 확인이 필요하다.

현재 GET 응답은 부분 추출 결과의 inputRevision을 제공하지 않는다. 폴링 사이 완료된 과거 부분 결과를 처음 수신하는 드문 경우 작성 표시가 일찍 해제될 가능성이 남는다. 최종 승인은 서버 completion까지 검사하므로 해당 결과로 신청할 수 없다. 보호 API 변경은 이번 범위에 포함하지 않는다.
