# 음성 통화 QA 수정

계약 0.2.0. 사용자 요구에 따라 통화 중에는 신청서 정보를 수집하고, 명시적인 **통화 종료·조회** 이후 서버가 초안을 저장하고 물품을 조회한다. 결과는 앱 안 알림과 요청함에서 확인한다. 실제 예약·결제·주민 전송은 자동 실행하지 않는다.

로컬 QA 스택에 반영 완료했다. 기존 접속 origin·DB·live 모델 설정을 보존하고 API·worker를 갱신했으며 API의 `contractVersion=0.2.0` 응답을 확인했다. 공유 DB 초기화·재생성은 하지 않았다. 기존 페이지를 새로고침하고 새 통화로 재검증한다.

## 확인한 원인과 수정

| QA 문제                          | 확인한 근거                                                                                          | 수정                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 첫 인사가 없음                   | 01:55–02:04 KST API 로그에서 voice.ready 뒤 null delegation thinking만 확인. 시작 발화 요청이 없었음 | 시작 developer input과 한 번의 greeting commentary                                                             |
| 드라이버에 사다리 추천           | DB 검색이 category만 필터링하며 queryText를 사용하지 않음                                            | 계약 패키지의 공통 물품명·동의어 검사. 서버와 mock 모두 적용. 구성 미상의 공구 세트도 드라이버로 취급하지 않음 |
| 오래된 정보 표시 가능            | sync가 임의 ID순인데 웹에서 마지막 task를 최신 추출로 사용                                           | 현재 통화의 완료된 form taskId를 서버가 전달. sync도 생성 시각순으로 정렬                                      |
| 자막이 최신 위치를 따라가지 않음 | 자막 영역에 자동 스크롤이 없었음                                                                     | 하단을 읽고 있으면 자동 추적, 위로 이동하면 위치 유지와 ‘새 대화 보기’ 버튼                                    |
| 사용자 발화 중 응답              | Live delegation을 발화 완료로 간주. 독립적인 Live 발화도 재생됨                                      | Decisions 완료·범위 검사, 최신 입력 revision 확인, 로컬 발화 시 재생 차단, 재생 준비 후 서버에 새 답변 요청    |

화면은 대화 말풍선, 점 모양 상담원 표시, 통화 조작부, 항목별 신청서로 구성했다. 통화 조작부는 신청서 위에 둔다. 날짜·장소가 빠졌으면 초안을 요청함에 저장해 보완하며, 완전한 조건만 기존 검색 worker에 전달한다. 신청서가 바뀌거나 취소된 뒤 도착한 이전 결과는 적용하지 않는다.

종료 POST의 응답을 잃어도 같은 명령을 재시도한다. 공급자가 먼저 session.closed를 보내더라도 재시도용 식별자를 보존한다. 다른 멱등 키를 사용해도 같은 음성 세션의 최종 작업은 하나다. 모델 출력이나 발화만으로 종료 후 저장·검색 권한을 얻을 수 없다.

## 검증 결과

- 전체 회귀 검사: **187개 통과**. 이후 재생·응답 유실 보완과 새 브라우저 클라이언트 회귀 2개를 포함한 web·api·AI 검사: **90개 통과**(앞의 검사와 중복 포함).
- 서버 수용 검사: **36개 통과**. 공유 개발 DB를 초기화하지 않고 테스트 전용 DB를 사용했다.
- 모든 workspace 타입 검사와 production 빌드 통과. production mock 제외와 API NetworkOnly 캐시 검사 통과.
- 실제 GPT-Live·Decisions·Responses 연결을 사용하는 데스크톱 Chromium 합성 음성 검사 3회 통과. 최신 기록: 실행 JSON (실행 산출물은 공유본에서 제외).
- 첫 인사 output transcript가 입력 transcript 전에 생성됨. 통화 중 검색·초안 저장 없음, 실시간 신청서 갱신, 종료 후 불완전 초안 저장, 작업 원문 제거, 브라우저 오류 없음 확인.
- 실제 Decisions에서 미완성 문장 WAIT, 지시 무시·키 공개 요청 UNSAFE, 무관한 역사 질문 OUT_OF_SCOPE 확인.
- 브라우저에 합성 자막 이벤트를 추가하여 자동 하단 추적, 이전 대화 위치 유지, 새 대화 버튼 복귀를 확인했다. 합성 자막은 공급자·서버 입력에 보내지 않았다.
- 화면: 통화·신청서 (실행 산출물은 공유본에서 제외), 종료 후 요청함 (실행 산출물은 공유본에서 제외).

## 아직 확인하지 않은 항목

사람이 실제로 듣는 음질·자연스러움·끼어들기 빈도, 갤럭시·아이폰 마이크와 오디오 정책, VoiceOver·TalkBack, 실기기 지연은 미검증이다. 합성 음성 통과와 greeting append 확인을 이 항목의 합격으로 기록하지 않는다. AT21·AT22는 별도로 확인해야 한다. 전체 기존 다자 브라우저 E2E 스택 전환 검사는 이번 변경에서 다시 실행하지 않았다.
