BUSINESS AUTHORITY

“알아서 승인해”라는 발화로 승인 권한이 생기지 않습니다. 종료·조회 버튼이 허용하는 효과도 저장·검색으로 제한합니다.

Live에 가짜 tools 배열을 붙이지 않습니다. 현재 client delegation에서는 앱이 백엔드를 실행합니다. 함수 호출이 필요한 작업에만 백엔드 Responses 도구를 등록하고, 반복 호출이 필요 없는 추출·분류는 고정 흐름을 유지합니다. [W4][W6]

개발 관점: 역할 명세와 실행 함수는 어떻게 나누나

아래는 제안하는 내부 인터페이스 예시입니다. 실제 SDK의 그대로 실행 가능한 API 예제가 아닙니다. 기능 이름은 기존 작업에 매핑하며, 별도의 중복 AI 호출을 추가하지 않습니다. 

// packages/ai/src/agents/voice-intake.ts — 제안
export const voiceIntake = {
  id: 'VOICE_INTAKE',
  modelKey: 'OPENAI_VOICE_MODEL',
  promptVersion: 'voice-intake/v1',
  instructions: voiceConversationInstructions,
  backendCapabilities: ['read_request', 'propose_request_summary'],
  policies: ['rental-scope', 'latest-turn', 'no-business-mutation'],
};

// packages/ai/src/tools/specs.ts — 모델 노출과 실행 효과를 구별
export const readRequestSpec = {
  name: 'read_request', inputSchema: EmptyArgsSchema,
  outputSchema: SafeRequestContextSchema, effect: 'READ_ONLY',
  policies: ['authenticated-session', 'request-owner'],
};

// apps/api/src/agents/bindings.ts — DB와 actor는 서버 문맥에만 둠
bindings.read_request = async (_args, ctx) =>
  ctx.db.transaction(async (u) => {
    await u.session(ctx.sessionToken);
    return toSafeContext(await u.getRequest(ctx.actorId, ctx.requestId));
  });

// registry와 실행 가드는 서버 코드가 소유.
// 모델이 actorId, sessionToken, finalizeAfterCall을 인자로 주지 않음.

04 / GUARDRAILS IN ACTION

가드레일은 실행 지점에 둡니다.

입력 분류만 통과했다고 모든 행동을 허용하지 않습니다. 아래 네 지점은 현재 검사를 재사용해 공통 실행 계약으로 묶는 제안입니다. [W3]

G1 · INPUT

들어오기 전에

완료된 발화인지, 서비스 범위인지 판정합니다. 분류 실패·WAIT는 실행을 열지 않습니다.

기존 Decisions 판정 재사용
G2 · EXECUTION

실행하기 전에

역할의 기능 목록, 입력 형식, 세션 권한, 현재 단계와 버전을 코드로 검사합니다.

기존 domain 검사 + 명시적 기능 목록
G3 · RESULT

반영하기 전에

스키마·ID·기간·가격 옵션·최신성을 확인합니다. 잘못된 결과는 저장·발화 문맥에 반영하지 않습니다.

기존 validation.ts + DB 재검증
G4 · OBSERVE

끝난 뒤 확인

차단 사유·버전·모델/프롬프트 버전·지연을 연결하고 같은 실패를 평가 사례로 남깁니다.

원문 없는 trace와 회귀 평가 강화

사례로 보는 통제 흐름

설계 시뮬레이션 · 실제 API 호출 없음

명시적인 사용자 명령

“토요일 오전에 프로젝터가 필요해요.”

통화로 필수 항목을 채운 후 사용자가 ‘통화 종료·조회’를 누릅니다.

초안 저장 · 조건 충족 시 검색 · 주민 전송은 별도 선택
  1. 1
    통화 중에는 제안만 갱신

    입력 완료·범위를 확인하고 신청서 추출 결과를 보여줍니다.

  2. 2
    종료 버튼에서 실행 근거 생성

    서버가 세션·CSRF·버전·멱등성을 확인합니다.

  3. 3
    검증된 최종 결과만 반영

    필수값과 기간이 유효하면 SEARCHING, 부족하면 DRAFT입니다.

음성의 재생 타이밍과 내용 안전성은 별도입니다. 현재 재생 게이트는 끼어들기를 줄이는 장치입니다. 이미 재생된 음성을 나중에 전사 검사해도 사전 차단이 되지는 않습니다. 우선 금액·상태는 서버 UI를 기준으로 안내하고, 음성의 허위 완료 표현을 평가합니다. 모든 음성을 검증한 뒤 재생하려면 실제 오디오 보류 경로와 추가 지연을 별도로 검증해야 합니다. [C6][W8]
정책의 세 층: 프롬프트, 모델 검사, 결정적 코드 검사

모델이 참고하는 규칙

  • 프롬프트: 역할, 범위, 질문 방식, 사용 예시.
  • Decisions: 발화 완료·범위에 대한 확률적 판정.
  • 자연어 요청·물품 설명은 비신뢰 데이터로 전달.

서버가 반드시 강제하는 규칙

  • actor는 세션에서 결정, 허용된 기능만 dispatch.
  • 사용자 명령의 효과·버전·멱등성을 DB에서 검사.
  • STRICT 스키마에 맞아도 권한·사실·최신성은 재검증.

비신뢰 텍스트를 시스템·개발자 지시로 승격하지 않고 데이터로 분리합니다. 이 방법도 모든 프롬프트 공격을 제거한다는 보장은 아니므로 실행 권한의 강제 검사가 필요합니다. [W7]

05 / IMPLEMENTATION PATH

기존 동작을 보존하며 단계적으로.

처음부터 범용 자율 루프를 도입할 필요는 없습니다. 변경 지점과 검증 기준부터 명시하고, 도구 선택의 유연성이 실제로 필요한 작업만 확장합니다.

STEP 1 · 정리

역할과 프롬프트를 모으기

각 역할의 목적·입출력·금지 효과를 정의하고, 프롬프트 조합과 버전을 한곳에서 관리합니다.

  • Live 대화 규칙과 업무 작업 규칙 분리
  • 현재 capability 설명 이름 정리
  • 계약 0.2.0 기준 문서 일치
완료 기준한 역할 정의에서 모델·지시·기능·정책·평가 ID를 찾을 수 있음.

STEP 2 · 연결

기능 명세와 실행 가드 연결

공통 실행 계층이 기존 API·worker·검증기를 호출합니다. DB 권한 경계와 사용자 명령 경로를 유지합니다.

  • 입출력 schema + handler binding
  • 허용 단계·효과·최신성 가드
  • 실패·취소·시간 예산 명시
완료 기준금지 호출은 handler 미실행, 오래된 결과는 미반영, 동일 종료 작업은 1개.

STEP 3 · 측정

평가와 음성 검증을 연결

실행 trace를 회귀 사례에 연결하고 실제 사람·휴대폰의 대화 품질을 측정합니다.

  • 정정·우회·실패·응답 유실 사례
  • 도구 선택·DB 결과·발화의 일치
  • AT21·AT22 실제 기기 관문
완료 기준안전·정확도·대화성 지표를 분리해 기록하고 기존 수용 기준을 충족.

W1 · Building agents ↗

W2 · Agent definitions ↗

모델이 보는 문맥과 코드가 쓰는 로컬 실행 문맥의 분리. actor·DB·토큰은 서버에 두는 제안의 근거입니다.

W3 · Guardrails and human review ↗

입력·출력·도구 가드의 적용 범위가 다릅니다. 실제 실행 지점의 검사를 역할 수준의 검사로 대체하지 않습니다.

W4 · Delegation and tools in GPT-Live ↗

client delegation에서는 앱이 문맥·실행·검증 결과를 관리합니다. 현재 구조를 유지하면서 서버 실행 계층을 정리하는 근거입니다.

W5 · Prompting GPT-Live ↗

음성 프롬프트는 대화 역할·말투·경청에 집중하고, 상세 업무 절차는 백엔드에 두도록 안내합니다.

W6 · Function calling ↗

도구 이름·용도·입출력을 명확히 정의하고 strict schema를 사용합니다. 권한과 실제 실행은 애플리케이션이 담당합니다.

W7 · Safety in building agents ↗

비신뢰 입력과 개발자 지시를 분리하고 구조화된 데이터로 전달합니다. 이 자료에서는 일반 보안 원칙만 참고하며 Agent Builder 도입을 제안하지 않습니다.

W8 · GPT-Live evaluation guide ↗

음성·위임·도구·최종 상태를 함께 평가하고, 합성 입력·사람 녹음·다중 턴 검증을 구분합니다.
