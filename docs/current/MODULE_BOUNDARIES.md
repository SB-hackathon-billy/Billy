# 모듈 경계

기준일: 2026-11-03. [3모듈 분담도](three-developer-architecture.png)의 기능 경계를 적용한다. 이름·개인 담당자는 기록하지 않는다. 이는 후속 개발 규칙이며 이번 정리에서 앱 기능은 바꾸지 않는다.

## 기능별 권한

| 모듈                    | 책임·데이터 소유                                                                                                                       | 후속 작업                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 1 · 접수 에이전트       | 채팅·보이스콜, 물품·기간 추출, 보완 질문, 신청서 확인, 3번 API를 통한 검색·비교·상태 안내. 대화·신청 초안·도구 실행 이력               | **기능·동작 수정 금지**. 현재 없는 1번 기능 추가도 제외 |
| 2 · AI 물품 등록        | 사진 업로드·분석 초안, 제목·분류·설명 제안, 사람의 수정·게시 확인, 가격·대여 가능 기간, 게시·수정·비활성화. 이미지·등록 초안·게시 물품 | 신규 개발·대체·통합 가능                                |
| 3 · 물품 탐색·대여 관리 | 목록·상세·필터·기간별 가용성, 신청·소유자 승인/거절·취소·만료, 중복 점유 방지, 대기·앱 알림. 예약·점유·대기·응답 이력                  | 신규 개발·대체·통합 가능                                |
| 기타                    | 센터 화면, 앱 셸, 데모 데이터, 인프라 등                                                                                               | 1번 동작을 보존하는 범위에서 교체 가능                  |

2·3번은 화면·API·데이터를 각각 완결한다. 모듈 간에는 HTTP·JSON 계약으로 연결하고 타 모듈의 저장소를 직접 수정하지 않는다. 1번은 접수·안내, 2번 AI는 등록 초안 작성 역할이다. 게시·신청·승인·취소는 사람의 확인과 소유 모듈 서버의 검증을 거친다. 3번은 2번 게시 물품과 자신의 점유 정보를 결합한다. AI가 자동 게시·승인·예약을 수행하지 않도록 한다.

현재 모놀리식 코드에 이미 존재하는 내부 호출을 이 문서만 보고 일괄 분리하지 않는다. 구현 언어·프레임워크·배포 단위는 2·3번에서 선택하되 1번 연결을 유지하는 전환 명세가 필요하다.

## 현재 접수 연결을 유지할 기준

현재 코드의 기준 commit은 `0d643d00b494e22fe2467616fb99a00b1df5ab11`이다. 다음은 보존할 동작 요약이며 새 모듈용 API 전체를 확정하는 명세가 아니다.

- 입력은 텍스트 또는 음성이다. 물품·기간·장소·선택 예산을 수집하고, 최신 정정과 누락 질문을 보존한다.
- 통화 중 추출 결과는 제안이다. 종료 전 실제 검색·주민 전송·승인·선택을 수행하지 않는다.
- 수동 종료 또는 서버의 수집 완료 확인과 브라우저의 종료 안내 자연 재생 완료 뒤 최종 처리한다. 새 발화·stale revision·오디오 중단으로 자동 종료를 우회하지 않는다.
- 최종 추출 후 불완전하면 초안, 완전하면 검색으로 연결한다. 같은 종료의 재시도로 중복 작업을 만들지 않는다.
- 세션·리소스 권한, 요청 버전, task/input revision, 원문 정리와 로그 비밀 제거를 유지한다.
- 접수 에이전트에 승인·선택·게시·결제·예약 상태 변경 권한을 추가하지 않는다.

현재 HTTP·DTO의 정확한 정의는 [http.ts](../../packages/contracts/src/http.ts), [ai.ts](../../packages/contracts/src/ai.ts), [OpenAPI](../../packages/contracts/openapi.json)에 있다. `/api/v1/requests`, `/agent-turns`, `/agent-tasks/{id}`, `/voice-sessions` 계열과 snapshot/SSE 연결을 함께 확인한다.

## 교체 시 경계 충돌 처리

그림의 `/requests/{id}/messages`, `/requests/{id}/voice-sessions`, `/catalog`, `/reservations`, `/item-drafts`는 **연동 API 초안**이다. 현재 구현됐다고 가정하거나 1번의 기존 경로를 바로 바꾸지 않는다. 특히 현재 `/requests`에는 접수 초안과 후속 대여 상태가 섞여 있다. 모듈 소유권을 먼저 분리하고 2·3번 쪽 호환 계층으로 기존 접수 호출을 유지한다.

[연동 준비 초안](../specs/0001-module-integration.md)에 겹치는 부분과 미결정을 정리했다. 1번의 기능 변경이 불가피하면 그 변경만 제안으로 남긴다. 2·3번의 독립 구현과 명세 작성은 계속할 수 있다.
