# boundary-review

## 1. 대상 범위

- 기본 대상은 이번 작업의 변경분이다: `git diff HEAD`와 새 파일. 개발자가 브랜치·커밋 범위를 지정하면 그것을 쓴다.
- 변경이 2·3번 내부 파일뿐이고 공용 파일·의존성·빌드 설정을 건드리지 않았다면 실행하지 않고 그 사실만 알린다. 개발자가 요청한 경우에는 실행한다.

## 2. 리뷰 위임

`reviewer` 에이전트 1개에 다음을 넘긴다.

- 변경 파일 목록과 diff 범위 (diff 원문 대신 확인할 명령을 줘도 된다)
- 변경 의도 한두 줄과 관련 명세 경로
- 바뀐 공용 파일 목록과, 그 파일을 쓰는 1번 소비자를 이미 찾았다면 그 목록

reviewer를 여러 개 띄우거나 모델·effort를 올려 다시 실행하지 않는다.

## 3. 결과 처리

- `차단` 지적은 고치고 관련 검증을 다시 실행한다.
- 1번 변경이 필요해서 고칠 수 없는 지적은 명세의 미결정 칸에 "1번 변경 필요 — 구현 보류"로 기록한다.
- 지적과 처리 결과를 개발자에게 요약한다. 명세가 있으면 1번 영향 칸에 리뷰 결과를 적는다.
